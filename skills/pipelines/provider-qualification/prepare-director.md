# Optional provider diagnostics preparation (beta)

This optional pipeline prepares one exact diagnostic result-contract sample. Ordinary production does not require it. A separately requested paid diagnostic needs strict approval; no retained Auto-continue policy may approve this test gate.

Read the selected manifest, `skills/meta/checkpoint-protocol.md`, `docs/OPENART_CLI.md`, and the registered OpenArt tools' Layer 3 skills before preparing settings. Discover the tools and present the real capability menu. Account probes are read-only; preparation does not submit or upload.

Retain `artifacts/provider_qualification_packet.json`, validated against its schema. Bind the current story revision, exact final prompt (UTF-8 SHA-256), governed request digest, native controls/argv/body hashes, exact profile hash, and current local compiled request and preparation review bytes. The compiled and review paths must be `artifacts/compiled_request-<compiled_request_id>.json` and `artifacts/preparation_review-<preparation_review_id>.json` for the actual request IDs. The packet's `native_no_reference` value must match the exact prepared request. A reference-free sample uses OpenArt text-to-video and has no source bindings, upload or media role. A referenced sample carries each approved role in `input_assets` with its project-relative `path`, source-byte `sha256` and retained `upload_id`. CLI 0.1.1 exposes one `--image` start-frame slot, but validate the full emitted `params` against the exact form, including nested required fields. The guarded preview omits `startFrame.id`, which H3 Turbo's captured image form requires; that role bind is not an eligible exact preview. Live-result qualification is optional; the exact native request still must satisfy the schema and transport checks. Do not prepare an end-frame, multireference or audio requirement for this CLI. The upload billing gate still applies: do not upload until a captured provider response explicitly confirms both nonspending and no delayed charge. An endpoint form or upload ID alone is not proof. All binding paths stay within the project and name retained files. Native/profile hashes must come from the observed exact preview and profile, never fabricated evidence.

The packet can describe exact source-bound assets, but current CLI reference verification does not accept role-bound `input_assets` as a verified transport. Do not dispatch that unsupported binding; packet/schema support alone is not transport support.

For a model whose native CLI preview omits one or more duration, aspect-ratio or resolution flags, packet `native_settings` must list only the explicitly sent values, with keys `duration`, `aspect_ratio` and `resolution`. Do not synthesize missing settings from form defaults or infer native controls from output-goal constraints. Do not mix `native_settings` with legacy top-level `duration`, `aspect_ratio` and `resolution`; packets without `native_settings` retain their existing three-field behavior.

The packet always describes **proposed** unknown-cost authorization, one original attempt and zero repairs. Name the exact scope, shot and proposed unknown-cost authorization ID, and present provider, model, mode, duration, aspect ratio, resolution, reference setting and exact native role bindings explicitly. The gate binds one singleton first-pass scope with allowance one and one unknown-cost authorization occurrence whose purpose is result-contract qualification. The later normal validator proves the separately retained human authorization against the frozen request, native preview, profile and source/upload evidence. Dollar cost and OpenArt credit charge remain unknown; no rate, guaranteed ceiling, refund or overdraft protection is claimed. For the separately approved plan's candidate sample, retain the exact 1s, 16:9, 720p PixVerse V6 reference-free text-to-video request unchanged. One second can prove transport and collection only.

Record an honest fresh preparation review. Write `prepare` as `awaiting_human` with the packet, present the exact request/settings, any source role and retained upload proof, unknown exposure and one-attempt/zero-repair limits, and end the turn. Local implementation approval is not user approval for this optional paid diagnostic. Only after the human separately approves this exact packet may `write_checkpoint` mark the preparation completed with `human_approved=True`. The packet itself stays proposed; the checkpoint is the approval record. Do not manufacture approvals or copy passing fixture reviews.
